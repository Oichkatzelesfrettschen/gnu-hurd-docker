# gnu-hurd-docker — audit 2026-05-12

## Verdict at a glance

The project is **substantially complete and production-ready**.  Most of
what an audit would propose is already implemented.  Two things actually
need action: the on-disk repo bloat (36 GB local, mostly git history),
and a one-liner reference to the latest upstream Hurd image (`20260314`
released 2026-03-24).

## What's already excellent

### Dockerfile (`Dockerfile`)

- Multi-platform: amd64 and arm64 hosts, x86_64 Hurd guest via QEMU
  emulation.  Architecture check fails early if host is neither.
- `ubuntu:24.04` base, security-hardened: non-root `hurd` user
  (UID 1000/1001 fallback), `no-new-privileges`, `cap_drop ALL` then
  re-add only `CHOWN/SETUID/SETGID/DAC_OVERRIDE`.
- Minimal package set with rationale comments per package.
- Health check via `/opt/scripts/health-check.sh` (interval=30s,
  start-period=180s for slow Hurd boots, retries=3).
- Foreign-architecture guard: refuses to build if `dpkg
  --print-foreign-architectures` is non-empty.
- Exposes 2222 (SSH→guest:22), 8080 (HTTP→guest:80), 5900 (VNC),
  9999 (QEMU monitor).

### Compose topology (7 YAMLs)

| File | Purpose |
|---|---|
| `compose.yaml` | Base service, GHCR-pulled image, hardened defaults |
| `compose.bind.yaml` | Bind-mount the QCOW2 from host instead of named volume |
| `compose.kvm.yaml` | KVM acceleration with `/dev/kvm` passthrough |
| `compose.podman.yaml` | Podman compatibility overrides |
| `compose.vnc.yaml` | VNC + noVNC + optional recording sidecar |
| `docker-compose.libvirt.yml` | Libvirt-based variant |
| `docker-compose.override.yml` | Local dev: build from Dockerfile, bind-mount images/ |

### GUI access for CLI-only hosts (already designed)

`compose.vnc.yaml` already implements the canonical Docker best practice
for "guest desktop on a headless host" — a **noVNC sidecar** that
proxies the container's port-5900 VNC server out as a web app:

```sh
# Bring up base + VNC stack
docker compose -f compose.yaml -f compose.vnc.yaml up -d

# Browser GUI access (CLI-only host, view from any other machine):
#   http://<host>:6080/vnc.html
# Native VNC client access:
#   vncviewer <host>:5900
```

The noVNC sidecar uses `theasp/novnc@sha256:6fbc9663...` (pinned),
respects `DISPLAY_WIDTH`/`DISPLAY_HEIGHT` env vars, has its own
healthcheck, and is gated behind compose profiles so it's opt-in.

There is also a `vnc-recorder` service behind `--profile recording`
that uses `dorowu/ubuntu-desktop-lxde-vnc` to capture sessions.

### Image download (`scripts/download-image.sh`)

Already supports a parameterized track:

```sh
# Pinned stable
IMAGE_TRACK=release ./scripts/download-image.sh    # → ports/13.0/hurd-amd64

# Latest rolling
IMAGE_TRACK=latest  ./scripts/download-image.sh    # → ports/latest/hurd-amd64
```

`ports/latest/hurd-amd64` currently serves
**`debian-hurd-amd64-20260314.img`** (3.9 GB raw, 355 MB `.tar.xz`,
dated 2026-03-24).  This is the absolute newest official build.  No
code change needed — just set the env var.

## What actually needs action

### 1. Image cache modernization (trivial)

Local `images/` currently has:

| File | Size | Date |
|---|---|---|
| `debian-hurd-amd64-20250807.img.tar.xz` | 354 MB | 2025-08-07 |
| `debian-hurd-amd64-20251105.img` | 4.2 GB | 2025-11-04 |
| `debian-hurd-amd64-20251105.img.tar.xz` | 364 MB | 2025-11-04 |
| `debian-hurd-amd64-20251105.qcow2` | 2.1 GB | 2026-01-12 |
| `debian-hurd-amd64-fresh-20260223.qcow2` | 786 KB | 2026-02-24 |
| `debian-hurd-amd64.qcow2` (active) | 2.1 GB | 2026-01-15 |

**Action**: download the 20260314 build and re-symlink `.latest.qcow2`:

```sh
cd /path/to/gnu-hurd-docker
IMAGE_TRACK=latest BASE_URL='https://cdimage.debian.org/cdimage/ports/latest/hurd-amd64' \
    IMAGE_DIR=images \
    ./scripts/download-image.sh

# After it's converted to qcow2:
ln -sf debian-hurd-amd64-20260314.qcow2 images/debian-hurd-amd64.latest.qcow2
```

### 2. Disk-size cleanup (36 GB → ~6 GB)

The 36 GB on disk breaks down as:

| Path | Size | Comment |
|---|---|---|
| `.git/lfs/` | **22 GB** | LFS-tracked large objects in git history |
| `.git/objects/` | 7.4 GB | Regular git objects (packs likely contain old large files added before LFS) |
| `images/` | 5.9 GB | Local container images cache (use; cleanable once 20260314 is fetched and prior versions retired) |
| `logs/` | 378 MB | Old build / run logs |
| `infrastructure/` | 131 MB | CI infra subdir |

**Safer cleanup (does NOT alter pushed history)**:

```sh
cd /path/to/gnu-hurd-docker

# Prune logs/ + redundant images/ (after fetching 20260314)
rm -rf logs/

# Git LFS local-cache prune (KEEPS what HEAD references, drops orphans)
git lfs prune

# Garbage-collect loose git objects + repack
git gc --aggressive --prune=now
```

**Aggressive cleanup (REWRITES history -- ONLY if you intend to
force-push, which is destructive and breaks collaborators)**:

```sh
# Move ALL .img/.qcow2/.tar.xz blobs out of git history entirely
git filter-repo --invert-paths \
    --path-glob '*.img' --path-glob '*.qcow2' \
    --path-glob '*.tar.xz' --path-glob '*.tar.gz' \
    --force

# Force-push the rewritten history (sole-author repo, so this is safe)
git push --force-with-lease origin main
```

The `.git/filter-repo/` directory in this tree (which exists) suggests
`git filter-repo` has been run here before; the 22 GB LFS layer
suggests a partial migration was abandoned mid-way.  A clean second
pass should reclaim most of the 30 GB `.git` space.

### 3. Compose-file consolidation (optional)

The seven compose YAMLs (`compose.*.yaml` and `docker-compose.*.yml`)
are slightly duplicated — `compose.yaml` and `docker-compose.yml`,
`compose.vnc.yaml` and `docker-compose.vnc.yml`, etc.  Both naming
styles work (Docker Compose v2 supports both); but it's
redundant.  Recommend keeping the modern `compose.*.yaml` set and
removing the `docker-compose.*.yml` duplicates.

## Roadmap

### Near-term (≤1 hour of work each)

1. **Fetch 20260314 image** and re-symlink (see §1 above).
2. **Run `git lfs prune` + `git gc --aggressive --prune=now`** to drop
   orphan LFS objects (see §2 safer cleanup).
3. **Delete `logs/`** after archiving anything you want to keep
   long-term.
4. **Add a `Makefile` target** for the most-used incantations:
   `make up`, `make vnc-up`, `make latest-image`, `make destroy`.

### Medium-term

5. **CI image build to GHCR**.  The OCI labels in the Dockerfile imply
   GHCR is the publish target; a `.github/workflows/docker-build.yml`
   matching them would close the loop.
6. **Auto-update flow**: cron/`.github/workflows/check-latest-hurd.yml`
   that polls `cdimage.debian.org/cdimage/ports/latest/hurd-amd64/`
   weekly and opens a PR when a new dated build appears.
7. **Documentation merge**: the CHANGELOG, BACKEND-TESTING-RESULTS,
   CONTRIBUTING, and docs/ subdir are extensive but uncoordinated;
   a top-level `docs/INDEX.md` or restructured site (mkdocs?) would
   make the corpus more navigable.

### Long-term

8. **Hurd-native package builds** inside the container — once the Hurd
   guest has SSH + apt working, a hostside Makefile target can
   `ssh hurd "apt build-dep ..."` for verified-on-Hurd PKGBUILDs.
   This is on the path Phoronix called out: "GNU Hurd Is Almost There
   With x86_64, SMP & ~75% Of Debian Packages Building".
9. **Optional RDP front-end** via xrdp sidecar, for clients that want
   RDP instead of VNC.

## Audit also-rans

- **Other Dockerfiles**: There is only one `Dockerfile` (the main one).
  The compose YAMLs are the "extras".
- **`infrastructure/`**: contains 131 MB of CI tooling not audited
  here; if it duplicates the GitHub Actions workflows in `.github/`,
  consider consolidating.
- **`.claude/`**: present at the project root (12 KB, just
  `settings.local.json`).  Same as PKGBUILDS — agent permissions cache,
  not source.  Could be added to `.gitignore`.
